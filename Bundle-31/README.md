# Bundle 31 — تبسيط تحكّم المقدّم بضغطة على الخلية

**سلّم للمستخدم ZIP واحد فقط: `Changes-Only.zip`**. استورد الملفين داخل مشروع Figma Make الحالي، ولا تستبدل مجلد `src` كله.

### الملفات المتغيرة فقط
- **MODIFIED** `src/letters/LettersPresenterDemo.tsx`: تبسيط واجهة المقدّم والتعامل المباشر مع الخلايا.
- **NEW** `src/letters/presenterLocalRules.ts`: منطق نقرات المقدّم التجريبية المبني على محرك اللعبة نفسه.

لا يحتاج تحديث `App.tsx` أو `LettersDemo.css` أو أي ملف من سين جيم. يعتمد على Bundle 30 الموجود مسبقًا.

### المسار المرئي
الرئيسية ← **استكشف لعبة الحروف** ← **تجربة دور المقدّم**.

1. اكتب الفريقين واختر عدد الجولات وابدأ.
2. الحرف الافتتاحي مضيء ويحدده النظام عشوائيًا، **الكبسة الأولى** عليه تفتح السؤال التجريبي (دون تغيير لونه).
3. **الكبسة الثانية** على نفس الحرف تجعله برتقاليًا، ويُغلق السؤال. **الثالثة** أخضر، و**الرابعة** محايد.
4. بعد الحرف الافتتاحي، أي خلية محايدة يمكن فتح سؤالها، وأي خلية ملوّنة يمكن تصحيح لونها مباشرة بنفس التسلسل.
5. لا حاجة إلى أزرار «صح الفريق الأول/الثاني» أو «خطأ/نقل الفرصة» أو «تصحيح لون خلية».
6. أثناء السؤال، تبقى **«استسلام الفريقين / كشف الإجابة»**. بعد كشف الإجابة، يبقى زر **«سؤال جديد لنفس الحرف»** (يمنع تلوين الحرف حتى سؤال جديد).
7. كشف الفوز والانتقال بين الجولات والنتائج يستخدم محرك `engine.ts` الأصلي. الفريقان يبدّلان الألوان بحسب رقم الجولة.
8. يبقى زر **«معاينة شاشة المتسابقين»** دون تعديل. يفتح قسمًا مصغرًا يشرح ما يظهر للمشاهد، وليس شاشة متصلة بجهاز آخر، ويخفي الإجابة قبل الكشف.

### حدود المرحلة
**تجربة محلية فقط:** لا إنشـاء غرفة، لا تسجيل دخول، لا API ولا Neon ولا حفظ بيانات. لم تُعدَّل خدمة `baleshhaarooms` الحقيقية أو قواعد صلاحياتها؛ **يجب تطبيق هذا السلوك لاحقًا على Backend/Live Host** قبل نشر الغرف الحقيقية. لا تغييرات على سين جيم.

### فحوصات التطوير
فحص strict TypeScript، اختبارات تسلسل أربع ضغطات، منع تبديل سؤال آخر أثناء السؤال المفتوح، استسلام وكشف ثم سؤال بديل، المسارات الفائزة برتقالي/أخضر، وحماية الإجابة على وضع العرض العام. تشغيلها عبر GitHub Actions `build-bundle31.yml`.
